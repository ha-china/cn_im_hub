Feishu
- Source: Feishu Open Platform
- URL: https://open.feishu.cn/
- npm: https://www.npmjs.com/package/@larksuiteoapi/feishu-openclaw-plugin
- npm latest: 2026.3.8
- Last checked: 2026-09-13
- Notes: npm package unchanged since 2026.3.8; its onboarding CLI still asks
  for manual appId/appSecret. The platform "one-click app creation" (扫码一键
  创建飞书智能体应用) is exposed via the official Python SDK lark-oapi >= 1.5.5:
  `lark_oapi.register_app` / `aregister_app` (RFC 8628 device grant against
  https://accounts.feishu.cn/oauth/v1/app/registration, init -> begin ->
  poll; base template presets bot capability, im scopes, im.message.receive_v1
  and WebSocket delivery; returns client_id/client_secret/user_info with
  open_id + tenant_brand; Lark tenants trigger domain_switched to
  accounts.larksuite.com). We adopted this in the Feishu subentry flow
  (providers/feishu/flow.py + auth.py, QR shown via segno data URL, manual
  entry kept as fallback).

WeCom
- Source: WeCom Open Platform
- URL: https://developer.work.weixin.qq.com/
- Source package: @wecom/wecom-openclaw-plugin
- npm: https://www.npmjs.com/package/@wecom/wecom-openclaw-plugin
- npm latest: 2026.8.17
- Source package: @wecom/wecom-openclaw-cli
- npm: https://www.npmjs.com/package/@wecom/wecom-openclaw-cli
- npm latest (cli): 1.1.1
- Notes: Official plugin supports Bot mode, Agent mode, interactive onboarding, multi-account routing, Agent/Bot webhook entrypoints, and Bot WebSocket to Agent HTTP fallback. Since 2026.8.17 the plugin replaced the `wecom_mcp` tool with a `wecom-cli` tool and rewritten `wecomcli-*` skills; core aibot WebSocket protocol commands are unchanged. No new release since the 2026-08-24 check.
- QR binding: wecom-openclaw-cli 1.1.1 dist/utils/qrcode.js implements
  scan-to-bind against the admin-side service:
  GET https://work.weixin.qq.com/ai/qc/generate?source=...&plat={1 darwin|2 win32|3 linux}
    -> {data:{scode, auth_url}} (auth_url is the QR content; fallback page
    https://work.weixin.qq.com/ai/qc/gen?source=...&scode=...)
  GET https://work.weixin.qq.com/ai/qc/query_result?scode=... (CLI polls 3s,
    5min TTL) -> {data:{status:"success", bot_info:{botid, secret}}}.
  Adopted in providers/wecom/auth.py + flow.py (poll once per submit).
- Last checked: 2026-09-13

DingTalk
- Source: DingTalk OpenClaw access docs
- URL: https://open.dingtalk.com/document/dingstart/build-dingtalk-ai-employees
- npm: https://www.npmjs.com/package/@dingtalk-real-ai/dingtalk-connector
- npm latest: 0.8.26
- Notes: 0.8.26 (2026-09-03) is entirely host/plugin-side: segmented plugin
  SDK entry points, host config snapshots, host-owned session queue and
  interrupt semantics, Channel Secret Contract, agent routing via the host;
  requires OpenClaw >= 2026.8.1. Only DingTalk-side change is a robustness
  guard for empty image-upload responses. No websocket/AI Card/message
  protocol changes - nothing to adopt for our Python integration.
- QR binding: 0.8.26 src/device-auth.ts implements one-click bot creation:
  POST https://oapi.dingtalk.com/app/registration/init {source:"DING_DWS_CLAW"}
    -> {errcode:0, nonce}
  POST .../app/registration/begin {nonce} -> {device_code,
    verification_uri_complete (QR content), expires_in (default 7200),
    interval (default 3)}
  POST .../app/registration/poll {device_code} -> {status:
    WAITING|SUCCESS|FAIL|EXPIRED, client_id, client_secret, fail_reason}.
  Scan with the DingTalk app; SUCCESS returns the same client_id/secret the
  manual path stores. Adopted in providers/dingtalk/auth.py + flow.py
  (poll once per submit).
- Last checked: 2026-09-13
